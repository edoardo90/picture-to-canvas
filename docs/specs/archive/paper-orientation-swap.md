# Paper Orientation Swap Button

## Objective

Give users a single tap/click to swap the paper width and height (toggling between portrait and landscape), so they can quickly match the paper orientation to their needs without re-selecting a preset or re-entering custom values.

## Acceptance Criteria

- [x] AC-1: A small icon button (using "⇅" or "↔", with an `aria-label` of **"Swap orientation"**) is rendered in the toolbar, immediately adjacent to the paper dimensions display (width × height).
- [x] AC-2: Clicking the button swaps the paper width and height values in `App.tsx` state — i.e. `widthCm` and `heightCm` are exchanged — and the coordinate display updates immediately to reflect the new orientation.
- [x] AC-3: The swap works whether the active paper size comes from a preset or from custom width/height values entered by the user.
- [x] AC-4: After a swap, pressing the button again restores the original values (the operation is a toggle — two taps return to the starting state).
- [x] AC-5: The button is keyboard-accessible: it is reachable by `Tab` and activatable by `Enter` or `Space`; a visible focus ring is always present.

## Out of Scope

- Any animation during the swap.
- Modifying `paperPresets.ts` — presets remain stored in portrait orientation; the swap only affects in-memory state.
- Automatically re-applying or resetting the swap when the user changes preset.
- Persisting the swapped state across page reloads.
- Interaction with the `paper-auto-orientation` feature (if both are implemented, they operate independently; auto-orientation is spec'd separately).

## NFR

- Performance: The swap is a single state update; no perceptible impact on rendering.
- Security: No user input is parsed; only two existing numeric state values are exchanged — no new attack surface.
- Accessibility: Minimum touch target 44 × 44 px. `aria-label="Swap orientation"` is required; a visible focus ring must always be shown.

## Notes

### Implementation details

- **Icon chosen**: `⇅` (vertical double arrows). The spec offered `⇅` or `↔`; `⇅` was selected as it more intuitively communicates portrait ↔ landscape.
- **State structure**: The spec notes described `widthCm` and `heightCm` as separate state variables. In practice they are properties of a single `paperSize: PaperSize | null` object. `handleSwapOrientation()` spreads the object with the two values exchanged in one `setPaperSize` call:
  ```ts
  setPaperSize({ ...paperSize, widthCm: paperSize.heightCm, heightCm: paperSize.widthCm })
  ```
- **Custom size sync**: When `selectedSizeId === 'custom'`, the parallel string states `customWidth` / `customHeight` are also swapped so the text inputs visually reflect the change.
- **Guard clause**: `handleSwapOrientation` is a no-op when `paperSize` is `null` (no paper size selected).
- **CSS**: `.app__swap-button` enforces `min-width: 44px; min-height: 44px` (NFR touch target). Focus ring is `outline: 3px solid #fff` on `:focus-visible`.

### Test coverage

- **9 unit tests** in `src/App.test.tsx` covering AC-1 through AC-5 (button presence, native element, preset swap, A4 swap, custom size swap, custom input field sync, round-trip toggle, keyboard focusability).
- **2 e2e tests** in `e2e/paper-orientation-swap.spec.ts`:
  - AC-2 + AC-4: swap changes point coordinates; swapping back restores them (landscape fixture, A4 preset).
  - AC-3 (image orientation variant): swap also works when a portrait photo is loaded. Custom paper size coverage for AC-3 is provided by unit tests only.
- Two new BMP fixtures (`landscape.bmp` 4×2 px, `portrait.bmp` 2×4 px) are generated by `e2e/create-fixtures.mjs` and regenerated automatically before every `test:e2e` and `test:e2e:ui` run via `package.json` scripts.

### Divergences from spec

| # | Divergence | Severity |
|---|-----------|----------|
| 1 | Spec Notes described `widthCm`/`heightCm` as separate state variables; they are actually properties of a `PaperSize` object. Behavior is identical. | Minor |
| 2 | `handleSwapOrientation` also syncs `customWidth`/`customHeight` string states (not mentioned in spec). This is necessary for the custom-input UI to stay consistent and is within the spirit of AC-3. | Minor |
| 3 | Second e2e test is scoped to photo orientation, not custom paper size (AC-3 custom coverage comes from unit tests). All acceptance criteria are still covered. | Minor |
